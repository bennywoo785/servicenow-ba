# 需求启发手册（Elicitation Playbook）

## 分级策略：按需求清晰度选择手段

### Level 1 — 常规启发（需求方向明确，细节待确认）
适用：客户有明确诉求（如"要 10 个服务目录项"），缺的是细节参数。
手段：结构化 Workshop + 问卷表（questionnaire）并行 + 每日 MOM。

### Level 2 — 深度启发（需求模糊，业务方自己也说不清）
适用：业务方只给出模糊目标或部分输入（如只提供 30% 信息）。
手段组合：
- **用户访谈**：与真实使用者一对一谈痛点
- **流程观察（shadowing）**：实地观察现状流程怎么跑
- **跨角色访谈**：一线执行者、供应商、合作方（跳出办公室）
- **竞品/类比分析**：参考同类产品的做法（如参考 POS 机的混合模式设计）
- **原型验证**：在 PDI 上做小原型演示给客户看，用具体画面收敛分歧
- **文档分析**：分析客户现有业务文档、旧系统数据
产出：把碎片发现整合成单一、开发可执行的需求描述，再交回客户确认。

## Workshop 操作规范（实测有效）

### 会前
- **议程先行**：每天一个主题/一个目录项，议程中写清具体名称（如"防火墙策略目录项"），让客户预期明确；提前发送议程。
- **先算排期**：按目录项复杂度估算天数（简单 = 1 天/项），确保 BRD/FRD 能在合同时间线内完成。
- **会前做功课**：文档分析在前，Workshop 用于收敛确认，不用于从零探索。

### 会中
- **先演示，再提问**：若客户不熟悉 ServiceNow，先完整演示一个已有目录项的全生命周期，再在同一语境下提问（SLA、审批层级、履约团队、变量）——客户回答质量会显著提高。
- **一次只谈一个目录项**：按议程收敛，防止发散。
- **业务决策归客户**：BA 展示 ServiceNow 中的可行形态供客户选择，不替客户做业务决定；技术不可行项明确说明。
- **同步起草 FRD**：Workshop 与 FRD 编制并行，结束时能演示当日产出的 FRD 片段。

### 会后（当天完成）
- 发 **MOM**（模板见 `assets/templates/mom-template.md`）：讨论要点逐条列出、双方行动项（责任到人+日期）、下次会议时间。
- 发/更新 **问卷表**（模板见 `assets/templates/questionnaire-template.md`）：让客户补填 SLA、审批层级、履约团队等参数。

## 经典启发式问题（迁移类项目）

1. 你们现在在用什么方式处理这个业务？（邮件/电话/旧工具如 SharePoint/无工具）
2. 挑一个典型场景，端到端讲一遍：用户如何发起 → 谁审批 → 谁履约 → 怎么结束？
3. 现状流程里最大的痛点是什么？
4. 如果搬到 ServiceNow，你希望保留什么、改变什么？

## HRSD 场景追加问题（本技能重点）

### HR 服务与工单类
1. 你们的 HR 服务如何分类？（COE 划分：薪酬福利/员工关系/人才管理等）
2. 员工主要通过什么渠道找 HR？（门户/邮件/电话/现场——决定 Employee Center 收敛策略）
3. 每类服务的敏感级别？谁可以看到工单内容？（权限与保密设计前置）
4. 是否存在"代他人提单"场景？（经理代下属、HR 代员工——影响 Subject Person 设计）

### Lifecycle Events / Journey 类
1. 入职/离职/转岗分别是哪些 Lifecycle Event 触发？触发条件是什么（HCM 状态变更/人工发起）？
2. 每个 Journey 分几个阶段（Stage）？每个阶段有哪些活动（Activity）？谁先谁后？
3. 每个 Activity 落地为谁的 Task？负责人是谁？超时怎么办？升级路径？
4. 哪些任务可以自动化？（账号开通、设备申请、文档签署——跨 HR/IT/行政）
5. 员工主数据从哪个 HCM 系统来？同步频率与字段映射？
6. 涉及哪些需要签署/生成的文档？（入职文件、在职证明——Document Template/eSignature）

## 反面信号（BA 失职预警）

- Workshop 全部开完仍有大量需求未确认未收敛
- 客户对 ServiceNow 没有概念就开始追问技术细节（缺演示环节）
- MOM 没有行动项或行动项没有责任人
- FRD 中出现"大概""可能"等模糊表述（FRD 必须精确）
